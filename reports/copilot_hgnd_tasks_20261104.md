## Общие инструкции рабочему агенту

- Отвечать только на вопрос конкретного task packet, по выбранным snapshot
  inputs. Каждый вывод связывать с файлом, строками либо JSON path.
- Различать проверенный факт, предложение и отсутствие данных. Отсутствующий
  вход обозначать BLOCKED или PARTIAL с конкретным недостающим артефактом.
- Не изменять файлы, scientific state, код, labels, cuts, calibration или окна.
  Не выполнять shell, модели, SSH, Slurm, сеть, другие агенты и MCP.
- Использовать только разрешённые read-only инструменты. Запрошены
  `gpt-6.1-terra` и effort `max`; наблюдаемые настройки учитывать отдельно.
  Не выбирать fallback и не повторять неудачную задачу автоматически.
- Не читать F outcomes для выбора метода или параметров. Старые F результаты
  допустимы только в явно выбранной ретроспективной сверке задачи 5.
  DCM test 988976, закрытые October17 кампании, AFT/HIC/f6v2 вне области работы.
- Не считать совпадение пересказа с summary независимой проверкой исходного
  вычисления. Не объявлять выигрыш Rₙ из AUC, MAE или relabelling.
- Результат: task_id, DONE/PARTIAL/BLOCKED, краткий вывод, evidence,
  findings с минимальным исправлением, acceptance_answers, unresolved,
  files_changed=[] в согласованном JSON-контракте.

Codex подготавливает компактный packet: выбранные исходники/вырезки с SHA и
номерами строк, нужные JSON sections и метаданные бинарных файлов. Полный
git status и повторяющиеся manifests в контекст рабочего агента не включать.
Copilot не должен угадывать содержимое NPZ или CSV по имени файла.
Первый packet — один вопрос из задачи 1; последующие выдаются отдельно.
Нативную цену и родительскую приёмку сохранять для каждого вызова.
Общий месячный лимит используется также другими проектами; локальный ledger
не доказывает остаток на аккаунте. Лимит CLI мягкий, не гарантия максимальной
конечной цены. Платных вызовов этим списком не выполнено.

## 1. Проверить готовность сохранённых входов для Rₙ

**Вопрос:** какие части сравнения native B0 и no-floor на прежней validation
можно вычислить без новых model calls и каких входов для остальных нет?

**Входы:** выбранные sections из
`reports/label_ablation_results_20261104/{input_pins.json,compact_manifest.json,collect.py}`,
`scripts/label_ablation_train.py`, `scripts/reco_rn_heldout.py`,
`results/smash_train_20261028/split/split_manifest.json` и существующие
primary-binding manifests, перечисленные родителем в packet.
Из больших manifests передавать выбранные записи, а не весь архивный индекс.

**Проверить:** candidate keys и порядок baseline; scores выбранного e_cls;
raw energy выбранного e_en; frozen B0 cuts по fold/seed; обе MC references;
content/Row/side/ClusterID; fixed primary truth и реальные exact bindings.
Разделить 290 validation groups и truth-bound S286; четыре unbound группы
сохраняются в detector-label диагностике, но не получают выдуманную primary truth.

**Выход и приёмка:** таблица «поле → источник → population → SHA/путь →
доступно/недостаёт». Отдельно readiness для reconstructed counts, каждого
доступного уровня C1–C4 и сравнения с T1. Не предполагать, что присутствие
агрегированного T1 обеспечивает нужные per-file counts на новой популяции.
Назвать минимальную дополнительную выгрузку, если она нужна.

## 2. Проверить план физического сравнения

**Зависимость:** принятая таблица задачи 1 и компактный план от Codex.

**Входы:** этот план, определения и readers из `scripts/reco_rn_heldout.py`,
`scripts/label_energy_audit.py`, принятый split и выбранные sections
`reports/label_ablation_protocol_20261103.md`.

**Проверить:** историческое определение
Rₙ = N(E ≥ 2 ГэВ) / N(0,3 ≤ E < 1 ГэВ), без верхнего ограничения числителя;
одинаковые candidates, truth, cuts и raw-energy policy двух arms;
строгое соединение по candidate keys без drop/intersection fallback.
Не сравнивать новый raw arm непосредственно с calibrated B1.

Предусмотреть пары потенциалов 18/0, 90/0, 90/18; парные разности arms;
совместное resampling целых файлов, одинаковое для сравниваемых arms и
производных контрастов. Не переносить старые F draws на другую S-популяцию.
Разделить file uncertainty и training-seed spread; folds не объявлять
независимыми повторениями. Для каждого уровня C1–C4 проверить фактическое
определение и доступные bindings. Validation уже участвовала в selection.

**Выход и приёмка:** конкретные нарушения/пропуски плана и минимальные fixes,
либо вывод, что он готов к проверке научным критиком. Copilot не подменяет
предзапускной review и не вычисляет новые Rₙ.

## 3. Проверить конкретный diff анализа Rₙ

**Зависимость:** после принятия задачи 2 Codex готовит ограниченный diff.
До появления diff задача не запускается.

**Входы:** только diff, затронутые функции, зафиксированный план и metadata
таблицы задачи 1.

**Проверить:** обработку границ 0,3/1/2 ГэВ, отсутствие нового score-cut fit,
разделение MC labels/initial MCTrack energy/reconstructed raw energy,
выбор e_cls/e_en, denominators и пустые группы, парность counts/draws,
неизменность primary truth. Для диагностики мягких объектов проверить
разделение common positives, added soft и остальных кандидатов.

**Выход и приёмка:** только воспроизводимые замечания со строками diff и
примером нарушения. Если замечаний нет — так и написать; новых функций,
экспериментов или переписывания тренера не предлагать без необходимости.
Решение об исполнении остаётся у Codex и научного критика.

## 4. Составить перечень недостающих входов для оптимизации окон

`reports/energy_label_first_principles_20261029.md`,

**Вопрос:** что ещё нужно для exact uncensored primary reduction и заранее

**Проверить:** какие сохранённые reductions уже отсечены по энергии; где

## 5. Сверить обновление отчёта с принятыми результатами

**Входы:** подготовленный Codex diff обновления полного SMASH/progress
отчёта; выбранные таблицы и JSON paths из no-floor README/results;
источники прежних potential-pair sections. Не передавать все отчёты целиком.

**Проверить:** baseline и no-floor явно разделены; native/disabled reference,
raw/calibrated energy, validation/F и SD/SE подписаны правильно; старые пары

новому числу есть source path и population. Rₙ не объявлен улучшенным до
принятого физического анализа. Новые графики отмечены как MC truth либо
reconstructed; подписи объясняют окно, отбор и тип погрешности.

**Выход и приёмка:** перечень конкретных расхождений «утверждение → источник
→ исправление» и пропущенных графиков. Принятые baseline F числа служат
источником сверки текста; настраивать по ним анализ запрещено. PDF render,

отдельными действиями родительского агента. Canonical/manuscript правки
в эту очередь не входят.
