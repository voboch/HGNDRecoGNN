# Редукция сравнения архитектур SMASH

Протокол оценки зафиксирован в [плане сравнения](../smash_architecture_comparison_plan_20261112.md). Редуктор принимает распакованные проверенные экспорты предсказаний. Для каждого scope нужны 18 каталогов с `summary.json` и CSV: два новых варианта, три исходных TEST-фолда, три seed. Архивные B0 GraphSAGE и его validation scans читаются по исходным хешам. Редуктор сравнивает train и validation состав каждого фолда, нативные targets, размеры и ключи кандидатов. Новый экспорт привязан к хешу квитанции 30-epoch fit. Нечётные экспорты должны ссылаться на одну и ту же квитанцию допуска.

В командной строке повторить `--prediction-bundle DIR` для всех 18 каталогов одного scope.

```text
python scripts/smash_architecture_reduce.py --scope even --output EVEN_RESULT --prediction-bundle DIR ...
python scripts/smash_architecture_reduce.py --scope odd --output ODD_RESULT --prediction-bundle DIR ...
```

По умолчанию оба запуска используют зафиксированный validation-порог с целевой 70% чистотой по нативным меткам и raw energy. Чётная редукция сохраняет полное распределение событий, включая нулевые, прямые связи, максимальные паросочетания и ошибку энергии. Фиксированный набор изолированных связей сравнивает оценки энергии до отбора. Для общего выбранного набора и собственного набора каждой модели приводятся отдельные оценки. В побиновых квантилях сохраняется принятый минимум 25 объектов для центральной оценки. Для пропусков и слияний повторно используется проверенная функция событийного подсчёта из [сравнения rules + ToF](../rule_tof_benchmark_20261110/reduce.py).

Нечётная редукция читает [архив целофайловых перевыборок](../rule_tof_odd_20261110/counts.npz) и фиксированные геометрические MC counts. Проверяются 282 файла, 1 165 216 событий и 63 усечённых диапазона с суммарно 91 отсутствующим событием. Жёсткость считается в открытой и ограниченной полосах. Основной показатель разброса контраста — выборочное SD по 400 файловым репликам. Приводятся обе границы Q16–Q84, полуширина, парный сдвиг от MC и его разность с GraphSAGE. Средний парный сдвиг модуля по трём seed и соответствующий тест с поправкой Holm хранятся отдельно от файловых интервалов.

При зарегистрированном дополнительном анализе запустить чётную редукцию с `--scan-rn`, сохранить и проверить `frozen_policy.json` перед нечётной оценкой. Общий потолок SD вычисляется из архивного raw70 GraphSAGE по чётным файлам. Для запуска нечётной редукции добавить `--frozen-policy EVEN_RESULT/frozen_policy.json`. При переносе проверяются квитанции fit и численные пороги. Если дополнительная рабочая точка недостижима, основная raw70 оценка остаётся доступной. Если недостижима основная 70% точка хотя бы для одного fit, квитанция сохраняет ROC-AUC/AP на общих кандидатах и перечисляет недостижимые рабочие точки.

В каждом выходном каталоге `file_counts.npz` хранит файловые счётчики и веса, `summary.json` связывает показатели с хешами источников. Пары с нулевым знаменателем помечаются как неопределённые, число таких перевыборок сохраняется. Графики и выводы строятся после проверки полного набора исходов. Исторический Dombay оценивается по собственному контракту, описанному в плане.
